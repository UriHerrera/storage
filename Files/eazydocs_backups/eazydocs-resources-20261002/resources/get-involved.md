Contributions can range from reporting bugs to maintaining or producing code. Any contribution, even the smallest, is valued.

### Areas of Contribution

- Artwork.
- Development (programming and packaging).
- Translation.
- Marketing.
- Quality Assurance (testing and bug triaging).
 
 To start contributing, create a GitHub account and [visit our organization](https://github.com/Nitrux/). ### Community

 Open an issue in the [Nitrux Bug Repository](https://github.com/Nitrux/nitrux-bug-tracker) using the feature request template. ### Release Schedule

 Nitrux follows a fixed-release cycle: - One new release every 60 days.
- We support each release for 60 days from the Release Announcement.
- After a new release, we only support the previous release for upgrades only (not bug reports) for 60 days.
- Releases older than that are unsupported.
 
 Nitrux does not follow major/minor versioning conventions. Releases with either suffix x.0.0 or x.1.0 do not indicate anything in particular; they are simply *releases* and may contain major changes either way. ### Development Schedule

- **Week 1** → Release day. Create OTA update archive. Begin work on the next release.
- **Week 2** → Review bug reports. Generate test builds for fixes.
- **Week 3** → Review feature requests. Generate test builds for new features.
- **Week 4** → QA tasks. Update the website and documentation, apply final fixes, and rebuild the ISO.
